
### 7.18. Files

Das Playdate SDK bietet verschiedene Möglichkeiten zum Lesen und Schreiben von Daten:

- **playdate.datastore** ist der einfachste Weg, um Tabellen und Bilder zu speichern oder zu laden.
- Erweiterte Dateioperationen sind über **playdate.file** möglich.
- Für das Kodieren oder Dekodieren von JSON-Dateien oder -Strings gibt es **playdate.json**.

_Hinweis:_ Im Simulator werden alle Dateioperationen im SDK-Ordner `Disk/Data/(bundleID)` ausgeführt. Das `bundleID` ist in der Metadaten-Datei des Projekts festgelegt.


### playdate.datastore

Die Datastore-APIs ermöglichen das einfache Speichern und Laden von Lua-Tabellen und Bildern.

### playdate.datastore.write(table, [filename], [pretty-print])
Speichert die angegebene Tabelle in einer Datei. Die Dateiendung `.json` wird weggelassen. Der Standard-Dateiname ist "data". Ist _pretty-print_ true, wird das JSON lesbar formatiert.

**Beispiel:**
```lua
local t = {score = 100, name = "Hans"}
playdate.datastore.write(t, "savegame")
```

### playdate.datastore.read([filename])
Lädt eine Tabelle aus der angegebenen JSON-codierten Datei (ohne `.json`). Standard-Dateiname ist "data". Gibt nil zurück, wenn keine Datei gefunden wurde.

**Beispiel:**
```lua
local t = playdate.datastore.read("savegame")
if t then
	print(t.score)
end
```

### playdate.datastore.delete([filename])
Löscht die angegebene Datastore-Datei. Standard-Dateiname ist "data". Gibt false zurück, wenn die Datei nicht gelöscht werden konnte.

### playdate.datastore.writeImage(image, path)
Speichert ein playdate.graphics.image-Objekt in einer Datei. Wenn _path_ keinen Ordnernamen enthält, wird das Bild im Ordner "images" gespeichert. Standardmäßig wird das PDI-Format verwendet, das mit `readImage()` wieder geladen werden kann. Für GIF-Ausgabe `.gif` an den Dateinamen anhängen.

**Important:** `writeImage()` unterstützt keine GIF-Transparenz. Wenn du ein GIF aus einem Image-Buffer speichern willst, muss das Bild mit `playdate.graphics.image.new(width, height, bgcolor)` erzeugt werden, wobei _bgcolor_ auf `playdate.graphics.kColorWhite` oder `playdate.graphics.kColorBlack` gesetzt sein muss.

### playdate.datastore.readImage(path)
Lädt ein playdate.graphics.image aus einer Datei im Datenordner. Wenn _path_ keinen Ordnernamen enthält, wird im Ordner "images" gesucht.

**Important:** `readImage()` kann nur kompilierte PDI-Dateien laden (Standardausgabe von `writeImage()`).


### playdate.file

Das Modul **playdate.file** enthält Funktionen zum Arbeiten mit Dateien auf dem Playdate-Dateisystem. Es gibt das Untermodul **playdate.file.file** für geöffnete Dateien.

#### Datei lesen und schreiben

### playdate.file.open(path, [mode])
Öffnet eine Datei und gibt ein playdate.file.file-Objekt zurück. _mode_ kann sein:
- **playdate.file.kFileRead**: Datei wird zum Lesen geöffnet (Standard). Es wird zuerst im /Data/<bundleid>-Ordner gesucht, dann im pdx-Ordner.
- **playdate.file.kFileWrite**: Datei wird zum Schreiben geöffnet (neu oder geleert).
- **playdate.file.kFileAppend**: Datei wird zum Anhängen geöffnet (neu oder ans Ende schreiben).

Wenn die Datei nicht geöffnet werden kann, gibt es einen zweiten Rückgabewert mit dem Fehler. Maximal 64 Dateien können gleichzeitig geöffnet sein.

**Beispiel:**
```lua
local file, err = playdate.file.open("test.txt", playdate.file.kFileWrite)
if file then
	file:write("Hallo Welt\n")
	file:close()
else
	print("Fehler:", err)
end
```

### playdate.file.file:close()
Schließt die Datei.

### playdate.file.file:write(string)
Schreibt den angegebenen String in die Datei. Gibt die Anzahl der geschriebenen Bytes zurück oder 0 und einen Fehler.

### playdate.file.file:flush()
Schreibt alle gepufferten Daten auf die Festplatte.

### playdate.file.file:readline()
Liest die nächste Zeile der Datei (endet mit `\n` oder `\r\n`). Die Rückgabe enthält keine Zeilenumbrüche.

### playdate.file.file:read(numberOfBytes)
Liest bis zu _numberOfBytes_ Bytes aus der Datei und gibt einen Buffer und die gelesene Byteanzahl zurück. Bei Fehler: nil und Fehlerbeschreibung.

### playdate.file.file:seek(offset, [whence])
Setzt die Lese-/Schreibposition in der Datei. _whence_ kann sein:
- **playdate.file.kSeekSet**: Absoluter Offset vom Dateianfang
- **playdate.file.kSeekFromCurrent**: Relativ zur aktuellen Position
- **playdate.file.kSeekFromEnd**: Relativ zum Dateiende (negativ = davor, positiv = danach)

### playdate.file.file:tell()
Gibt die aktuelle Byteposition in der Datei zurück.


#### Dateisystem-Operationen

### playdate.file.listFiles(path, [showhidden])
Gibt ein Array mit Dateinamen im angegebenen Verzeichnis zurück. Ordner werden mit einem Schrägstrich `/` am Ende angezeigt. Mit _showhidden_ werden auch versteckte Dateien angezeigt. Ohne Argument werden alle Dateien und Ordner aufgelistet, auf die das Spiel Zugriff hat.

### playdate.file.exists(path)
Gibt true zurück, wenn eine Datei am angegebenen Pfad existiert. Der Pfad muss die Dateiendung enthalten. Kompilierte Asset-Dateien haben oft andere Endungen: z.B. `.wav`/`.aiff` werden zu `.pda`, `.gif`/`.png` zu `.pdi`.

### playdate.file.isdir(path)
Gibt true zurück, wenn ein Verzeichnis am angegebenen Pfad existiert.

### playdate.file.mkdir(path)
Erstellt ein Verzeichnis am angegebenen Pfad (unter /Data/<bundleid>). Alle Zwischenverzeichnisse werden bei Bedarf angelegt.

### playdate.file.delete(path, [recursive])
Löscht die Datei am angegebenen Pfad. Gibt true zurück, wenn erfolgreich. Bei _recursive = true_ wird das Verzeichnis samt Inhalt gelöscht, sonst muss es leer sein.

### playdate.file.getSize(path)
Gibt die Größe der Datei am angegebenen Pfad zurück.

### playdate.file.getType(path)
Gibt den Typ der Datei am angegebenen Pfad zurück.

### playdate.file.modtime(path)
Gibt das Änderungsdatum der Datei als Tabelle zurück mit den Schlüsseln: year, month, day, hour, minute, second.

### playdate.file.rename(path, newPath)
Benennt die Datei am Pfad _path_ in _newPath_ um. Ordner werden dabei nicht automatisch angelegt. Gibt true zurück, wenn erfolgreich.


#### .pdz-Dateien

### playdate.file.load(path, [env])
Lädt die kompilierte .pdz-Datei am angegebenen Pfad und gibt den Inhalt als Funktion zurück. Die Endung .pdz ist optional. Mit _env_ kann eine eigene Umgebungstabelle als globaler Namespace verwendet werden.

### playdate.file.run(path, [env])
Führt die pdz-Datei am angegebenen Pfad aus. Entspricht `playdate.file.load(path, env)()`. Rückgabewerte der Datei bleiben auf dem Stack. Die .pdz-Endung ist optional. _env_ kann als Umgebungstabelle übergeben werden.
